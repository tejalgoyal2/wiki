## This week

> [!question]- Lesson 1. After a script finishes, a `setTimeout(fn, 0)` callback and a `.then` callback are both waiting. Which runs first, and why?
> The `.then` callback. It is a [[microtask-queue|microtask]], and the whole microtask queue is emptied as soon as the
> current task ends. The timer callback is a task in the [[task-queue|task queue]], so it waits for the next turn of the
> [[event-loop|event loop]]. From [[2026-11-11-event-loop|#1 · The event loop]].

> [!question]- Lesson 2. `a = [1, 2]`, `b = a`, `b.append(3)`. What is `a`, and what does `a is b` say?
> `a` is `[1, 2, 3]`, and `a is b` is `True`. Assignment binds a second name to the same
> [[mutability|mutable]] object; it does not copy. Use `a.copy()` for a [[shallow-vs-deep-copy|shallow copy]] and `copy.deepcopy(a)` when the
> list holds other mutable objects. From [[2026-11-12-python-object-model|#2 · Python's object model]].

> [!question]- Lesson 3. Training error keeps dropping while validation error starts rising. What is happening, and what do you do?
> The model is [[overfitting|overfitting]]: it is fitting noise in the training data, so variance is growing faster
> than bias is shrinking. Pick the model complexity (or stop the training) where validation error is lowest, get more
> data, or simplify the model. Never use the [[train-validation-test-split|test set]] to make this choice. From
> [[2026-11-13-overfitting|#3 · Overfitting and the bias-variance trade-off]].

> [!question]- Puzzles. Two Sum, Contains Duplicate and Valid Anagram all use the same pattern. What is it, and what does the map store each time?
> [[hash-map-lookup|Hash map lookup]]: one pass, trading [[big-o-notation|O(n)]] memory for O(1) checks. [[two-sum|Two Sum]] stores
> `value -> index` and looks up `target - x`. [[contains-duplicate|Contains Duplicate]] stores values seen so far. [[valid-anagram|Valid Anagram]] stores
> `letter -> count`. Each replaces an O(n²) pair search or an O(n log n) sort with O(n).

> [!question]- Mixed. You scale every feature using the mean of the full dataset, then split into train and test. Which lesson's idea does that break?
> Lesson 3: [[data-leakage|data leakage]]. The test rows influenced the scaler, so the test score is too optimistic. Fit
> the scaler on the training rows only, then apply it to validation and test.

## Mock interview

**Technical question.** "Explain what happens when you call `setTimeout(fn, 0)` and then resolve a [[promise|promise]] in the same
script. In what order do they run, and why?"

> [!question]- Model answer (about 150 words, spoken style)
> "Both callbacks are queued, but into different places. `setTimeout` hands the callback to the browser's timer, and
> when the delay is over, the callback goes into the task queue. The resolved promise puts its `.then` callback into
> the microtask queue. The event loop runs one task at a time, which here is the script itself. When that task
> finishes, the loop drains the whole microtask queue before it takes the next task. So the promise callback runs
> first, and the timer callback runs afterwards, even with a delay of zero. The practical consequence is that a long
> chain of microtasks can starve rendering and timers, because the browser cannot paint until the microtask queue is
> empty. If I wanted to yield to the browser, I would use a task, such as `setTimeout`, not another promise."

**Behavioral question.** "Tell me about a time you found a bug that only appeared sometimes." Fill in your own
answer using STAR. Write one or two sentences for each part:

- **Situation:** what was the project, and what was failing?
- **Task:** what were you responsible for fixing?
- **Action:** how did you make the bug repeat, what did you check first, and what did you change? Name a real tool or technique.
- **Result:** what was fixed, how did you know, and what did you add (a test, a log, a check) so it would not come back?

Tip: pick a story where you can say what you learned about timing, shared state or data, so it links back to this
week's lessons.
